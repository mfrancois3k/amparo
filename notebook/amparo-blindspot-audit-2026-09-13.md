## CRITICAL

### C1 — Privacy page falsely states "Marketing analytics and session recording are disabled"
- **Files:** `privacy/index.html:63`, `privacidad/index.html:63`
- Both dedicated privacy pages assert, site-wide, under "Website metrics and
  technical reports": *"Marketing analytics and session recording are disabled."*
  (ES: *"Los análisis de marketing y las grabaciones de sesión están desactivados."*)
- This is affirmatively false:
  - **Analytics IS running** on `/` (`new/index.html:56-63`), `/pack`
    (`pack.html:1263`), and `/aid` (`new/aid.html:35-37`) — PostHog with
    `capture_pageview:true` plus explicit `posthog.capture(...)` calls and
    first-touch UTM/fbclid campaign attribution (`pack.html:1284-1355`).
  - **Session recording IS enabled**, scoped to steps 0–1 of the pack builder:
    `pack.html:3185` calls `posthog.startSessionRecording()`; `init` sets
    `disable_session_recording:true` as the default but `srReplayGuard()`
    re-enables replay for the first two screens (`pack.html:3178-3186`,
    `pack.html:1273,1281`).
- It also directly contradicts the site's own homepage disclosure
  (`new/index.html:540`, `privacyBody`): *"We count anonymous, non-identifying
  usage — how many packs get built, and in which state."* The v2.29.5 work fixed
  the homepage copy but the authoritative `/privacy/` + `/privacidad/` pages were
  left saying the opposite.
- On a trust-first know-your-rights product the privacy page is the load-bearing
  legal statement; a hostile reviewer (or a regulator) reads this as a material
  misrepresentation.
- **Fix:** rewrite line 63 in both languages to match reality — e.g. "We use
  privacy-preserving product analytics (PostHog, self-hosted proxy) to count
  anonymous usage; autocapture and surveys are off, inputs are masked, and
  session replay is limited to the first two setup screens (no documents,
  contacts, or typed answers). No third-party ad/marketing trackers."

- **File:** `sitemap.xml` (whole file; `grep -n "organiz" sitemap.xml` → no match)

  the daily cron doesn't drop them again — UNVERIFIED which tool emits the
  sitemap (not traced).

## MEDIUM

### M1 — Homepage ships an empty `<body>`; all text (incl. `<h1>`) is JS-rendered, no `<noscript>`
- **Files:** `new/index.html:452` (`<main id="app"></main>`), copy injected at
  `new/index.html:956+` (`'<h1 id="encounterTitle">'+esc(c.heroTitle)+'</h1>'…`)
- The highest-priority sitemap page (`/`, priority 1.0) has no server-rendered
  body content and no `<noscript>` fallback. The `<title>` and `og:*` are static
  in `<head>` (so social cards are fine), but the H1 and all on-page copy exist
  only after JS runs. robots.txt explicitly courts crawlers ("Crawling it is the
  point"); non-rendering crawlers and many LLM/AI crawlers will see an empty page.
- Googlebot renders JS so this is a risk, not a guaranteed failure, hence MEDIUM.
- **Fix:** add a `<noscript>` block (or a static hero H1 + intro paragraph in the
  `<main>` that JS replaces) so the primary value prop is in the raw DOM.

## LOW

### L1 — Privacy footer links to `/organizations` but org canonical is `/organizations/`
- **File:** `privacy/index.html:68` (`<a href="/organizations">`) vs
  `organizations/index.html:8` canonical `…/organizations/`.
- Vercel serves the directory index at both spellings, so it resolves; only a
  cosmetic trailing-slash inconsistency. Prefer the trailing-slash form to match
  canonical and avoid a needless normalize hop.

### L2 — Org pages (and privacy pages) omit `hreflang="x-default"`
- **Files:** `organizations/index.html:9-10`, `organizaciones/index.html:9-10`
  (also the privacy pair). en↔es alternates are reciprocal and self-referential
  (correct); Google merely recommends an additional `x-default`. Optional.

### L3 — Orphan file `new/rehearse.html` is reachable but unlinked and not in sitemap
- `/rehearse` is a rewrite to `/arena/index.html` (`vercel.json:181-186`);
  `new/rehearse.html` is referenced nowhere (`grep` for `new/rehearse` → none)
  yet is directly fetchable at `/new/rehearse.html`. Dead surface. Consider
  deleting or `.vercelignore`-ing it. (Contains its own "all 50 states" federal
  copy, which is honest, so not a coverage problem — just clutter.)

### L4 — Org-page conversions are unmeasured
- `organizations/` and `organizaciones/` load zero JS / no PostHog (good for CSP
  and privacy), but the sole conversion is the `mailto:` CTA, which analytics
  can't see. Expected for a static page; noted so nobody later concludes "the
  org page gets no interest" from empty PostHog data.
